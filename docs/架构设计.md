# td-pi 架构设计

> td-pi 是 pi coding agent 的 Windows 桌面管理器。本文描述其模块划分、预设注入机制与数据流。

## 一、系统全貌

```
┌──────────────────────────────────────────────────────────────┐
│ td-pi 管理器(Avalonia 自包含发布)                              │
│  预设管理 · 启动预设 · 会话记录 · 技能 · MCP · 插件 · 自定义模型     │
└────────┬──────────────────────────────┬──────────────────────┘
         │ 读写配置文件(JSON/Markdown)    │ 编译预设 → argv + 启动批处理
         ▼                              ▼
~/.pi/agent/ 等 pi 配置            新终端窗口(wt / cmd)
├── settings.json   ← 包/扩展路径启停    set TD_PI_PRESET=<名称>
├── extensions/     ← 本地扩展启停       set TD_PI_PRESET_DIR=<预设目录>
├── skills/         ← 技能启停          cd /d <项目目录>
├── mcp-adapter.json← MCP 全局覆盖       pi --system-prompt <编译块.md> \
├── models.json     ← 自定义模型            -n <会话名> [更多参数] "开场白"
└── sessions/       ← 会话记录(只读+删除)
                                          │
                                          ▼
                    ~/.pi/agent/extensions/td-pi-preset/index.ts
                    (管理器「诊断」页一键部署;负责上下文注入与会话记录)
```

## 二、模块划分

| 项目 | 职责 |
|---|---|
| `src/TdPi.Core` | 无 UI 服务层:预设/技能/MCP/插件/模型/会话/启动/环境探测/扩展部署 |
| `src/TdPi.App` | Avalonia 桌面应用:每页一个 ViewModel + View,CommunityToolkit.Mvvm |
| `extension/td-pi-preset` | pi 扩展(TypeScript,嵌入 App 资源,运行于 pi 内置 jiti) |

Core 服务与文件系统的对应:

| 服务 | 管理对象 |
|---|---|
| `PresetService` / `PresetCompiler` | `<项目>/.pi/td-pi/presets/<名称>/preset.json` → 编译为 pi 启动参数 |
| `SkillService` | 全局/项目技能目录;启停 = `SKILL.md` ↔ `SKILL.md.disabled` 重命名 |
| `McpService` | 六层 mcpServers 配置合并;启停写适配器覆盖层(`{"disabled":true}`) |
| `PluginService` | settings.json `packages[]`(对象形式空资源过滤=禁用)、extensions 目录(`.disabled` 重命名)、settings `extensions[]`(`+`/`-` 前缀) |
| `ModelSettingsService` | `models.json` 服务商/模型 CRUD(编辑时克隆原对象,保留未识别扩展字段) |
| `SessionService` | 扫描解析 `~/.pi/agent/sessions/<项目>/*.jsonl` |
| `LaunchService` | 生成启动批处理(env 注入 + `cd /d` + pi 命令行)并在新终端窗口运行 |
| `ExtensionDeployer` | 把内嵌的 td-pi-preset 扩展部署到 `~/.pi/agent/extensions/td-pi-preset/` |

## 三、预设注入机制

预设(`preset.json` 的 `messages[]`)按角色走两条通道:

**1. 系统消息 → 系统提示词层**

- 编译器把启用的系统消息原文按顺序拼接(空行分隔,无任何标记/标题)写入编译文件;
- 以 `--system-prompt <编译文件>` 启动,pi 用它**替换**默认系统提示词;
- 系统提示词不参与上下文压缩 → 系统消息**永不压缩**。

**2. 用户/AI 消息 → 上下文消息(td-pi-preset 扩展)**

- 管理器启动时设环境变量 `TD_PI_PRESET` / `TD_PI_PRESET_DIR`;
- 扩展在 `context` 事件(每次 LLM 调用前)把启用的 user/assistant 消息构造成消息对象,拼到真实对话之前;
- 上下文消息**不写入会话文件**,每次请求动态重拼 —— 上下文压缩只作用于会话条目,对注入不可见 → **永不压缩**;
- 压缩摘要调用走独立通道,不经过 `context` 事件,注入不会污染压缩过程。

**会话延续**

- 扩展在 `session_start` 把生效预设写入会话(`customType: "td-pi-preset"` 记录);
- 用户手动 `pi --continue` / `pi --session` 恢复时,扩展从会话记录读取预设名,在 `before_agent_start` 补注入系统块,并继续重拼上下文消息;
- 管理器启动(环境变量存在)时扩展不再重复注入系统提示词,两条通道互认。

**会话识别(会话记录页)**

1. 主识别:会话中的 `td-pi-preset` custom 记录(预设名/来源/注入条数);
2. 兜底:旧版(v1.3-)系统提示词注入块标记 `<!-- td-pi-preset:begin name=X -->`,仅在 system 消息行内识别避免误判。

## 四、MCP 配置层级(低 → 高)

1. `~/.config/mcp/mcp.json` 全局共享
2. `~/.agents/mcp.json` 全局兼容
3. `~/.agents/mcp/mcp.json` 全局兼容
4. `~/.pi/agent/mcp-adapter.json` 全局适配器覆盖
5. `<项目>/.mcp.json` 项目共享
6. `<项目>/.pi/mcp-adapter.json` 项目适配器覆盖(最高)

服务器级替换合并;`disabled` 字段为启停开关。td-pi 的启停写入对应作用域的适配器覆盖层,与 pi-mcp-adapter 自身的 `/mcp-adapter enable|disable` 行为一致,不污染共享配置文件。

## 五、插件启停语义(与 pi 一致)

| 对象 | 禁用 | 启用 |
|---|---|---|
| Pi 包(settings `packages[]`) | 对象形式,extensions/skills/prompts/themes 四个空数组(完全过滤) | 字符串形式 |
| 本地扩展(extensions 目录) | 入口文件重命名 `index.ts` → `index.ts.disabled` | 重命名还原 |
| settings `extensions[]` 条目 | `-path`(排除) | `+path`(显式加载,与 pi 配置选择器行为一致) |

## 六、启动流水线

「▶ 启动预设」→ `PresetCompiler.Compile`:

1. 系统消息 → 编译文件(`%LOCALAPPDATA%\td-pi\compiled\<预设名>-<目录哈希>.md`)→ `--system-prompt`;
2. 会话名 → `-n`;
3. 扩展/技能声明 → `-e` / `--skill`(独占模式加 `--no-extensions` / `--no-skills`,基础设施除外);
4. MCP 配置 → `--mcp-config`(前置校验:文件存在、pi-mcp-adapter 已安装,否则给警告);
5. 工具/文件存在性校验 → 警告列表(UI 展示);
6. 生成批处理:`set TD_PI_PRESET[_DIR]` + `cd /d <项目>` + pi 命令行 + 开场消息;
7. 新终端窗口运行(优先 Windows Terminal,回退 `start cmd /k`)。

## 七、发布

`publish.cmd`:`dotnet publish -c Release -r win-x64 --self-contained` → 单目录免依赖输出。td-pi-preset 扩展以嵌入资源随 App 分发,由「诊断」页部署,保证管理器与扩展版本同步。
